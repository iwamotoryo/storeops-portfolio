# システム構成（一般化）

> 本ドキュメントは、実案件を一般化したシステム構成の例です。具体的な本番環境の構成情報（ドメイン、IPアドレス、ポート、内部URLなど）は含めていません。

## 実案件で使っている構成パターン

案件の性質に合わせて、次の3つの構成を使い分けています。各案件の詳細は [ケーススタディ](../README.md#selected-projects) を参照してください。

| パターン | 構成 | 採用した案件 | 選んだ理由 |
| --- | --- | --- | --- |
| A. フルスタック Next.js | Next.js（Server Components / Server Actions）＋ Prisma ＋ PostgreSQL、VPS 上で PM2 と Nginx | 美容室、ドッグサロン | 画面と業務ロジックを一つのコードベースで持ち、一人でも速く改善を回せる |
| B. API ファースト | FastAPI（管理画面は Jinja2、公開API は JSON）＋ PostgreSQL、公開サイトは Next.js、Docker Compose ＋ Nginx | レンタカー | 公開サイト・LINE Mini App・管理画面が同じ予約ルールを使うため、ルールをバックエンドに集約する |
| C. ローカルファースト | Next.js ＋ IndexedDB（Dexie）、教室機能は Supabase | 宅建学習 | ログイン不要ですぐ使え、通信が切れてもデータが消えない |

## 全体像（パターン A）

```
[店舗スタッフ]            [顧客（LINE / ブラウザ）]
       │                          │
       ▼                          ▼
[Next.js アプリ（管理画面・顧客向け画面）]
   ├─ Server Components：DB から直接読み込み
   └─ Server Actions：更新処理（冒頭で認証・権限チェック）
       │
       ├──► [PostgreSQL（Prisma）]
       └──► [LINE / メール（サーバー側から送信）]

VPS 上で PM2 がプロセスを管理し、手前に Nginx を配置
```

## 全体像（パターン B）

```
[公開サイト (Next.js)]  [LINE Mini App (LIFF)]  [管理画面 (Jinja2)]
          │ 公開API               │ 会員API（JWT）          │ セッション
          └──────────────┬───────┴──────────────────────┘
                         ▼
               [FastAPI（業務ロジック）]
                 ├─ 空き判定・料金計算（共通サービス）
                 └─ 通知メール
                         │
                         ▼
                   [PostgreSQL]

DB・API・公開サイトを Docker Compose で起動し、
手前に Nginx（リバースプロキシ・SSL終端）を配置
```

## フロントエンド

- Next.js / React / TypeScript / Tailwind CSS
- 店舗スタッフ向けの管理画面と、顧客向けの画面（予約・マイページなど）を提供
- 顧客向けの画面は LINE 内のブラウザやスマートフォンでの操作を優先

## バックエンド

- パターン A：Next.js の Server Actions に業務ロジックを置き、Prisma で DB を操作
- パターン B：FastAPI の API サーバーに業務ロジックを置き、SQLAlchemy で DB を操作
- どちらも、金額計算や空き判定など「同じルール」は一か所の共通処理にまとめる
- 入力値の検証と権限チェックはサーバー側で行う

## データベース

- PostgreSQL を採用
- スキーマ変更はマイグレーション（Prisma Migrate / Alembic）経由のみ。本番DBを手で直接変更しない
- 変更前のバックアップと、復旧・再取込の手順を文書化

## 管理画面

- 店舗スタッフ・管理者が使う業務画面
- 権限（オーナー / 管理者 / スタッフ / 経理 など）に応じて、閲覧・操作できる範囲を分ける

## LINE連携

- LINE Login による本人確認（PC ブラウザ向けの OAuth と、LINE 内の LIFF）
- LIFF を使った、アプリのインストールが不要な予約・マイページ
- Messaging API による通知（サーバー側から送信）
- Channel Secret やアクセストークンは環境変数で管理し、コードや公開リポジトリには含めない

## VPS / Nginx / デプロイ

- Linux ベースの VPS 上で運用
- Nginx をリバースプロキシとして配置し、HTTPS の終端とルーティングを担当
- 同じ VPS で複数のシステムを動かす場合は、デプロイ手順で他のシステムに触れないようにガードする

## 注意（本番構成情報について）
