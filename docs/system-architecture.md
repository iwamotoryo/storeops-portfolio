# システム構成（一般化）

> 本ドキュメントは、実案件を匿名化・一般化した店舗業務システムの全体構成例です。具体的な本番環境の構成情報（ドメイン、IPアドレス、サーバ台数、ポート、内部URLなど）は含めていません。

## 全体像

店舗業務システムは、おおまかに次の層で構成されます。利用者（店舗スタッフ・エンドユーザー）からのリクエストを、フロントエンドが受け取り、バックエンドAPIを通じてデータベースとやり取りします。LINEなどの外部サービスとは、バックエンドを経由して連携します。

```
[利用者・スタッフ]
        │
        ▼
[フロントエンド (Next.js / React)]
        │  HTTPS / API呼び出し
        ▼
[バックエンド API (FastAPI / Python)]
        │
        ├──► [データベース (PostgreSQL / MySQL)]
        │
        └──► [外部サービス連携 (LINE など)]

すべて [Docker] 上で動作し、
手前に [Nginx]（リバースプロキシ）を配置、
[Linux / VPS] 上で運用する。
```

## フロントエンド

- Next.js / React / TypeScript で構築
- 店舗スタッフ向けの管理画面と、エンドユーザー向けの画面（マイページなど）を提供
- バックエンドAPIとはHTTPS経由で通信
- 入力チェックや画面遷移など、利用者が迷わない操作性を重視

## バックエンド

- FastAPI / Python で構築したAPIサーバ
- 認証、予約、顧客、売上、料金計算などの業務ロジックを担当
- データベースアクセスと外部サービス連携を仲介
- 入力値の検証と権限チェックをサーバ側で実施

## データベース

- PostgreSQL または MySQL を案件に応じて採用
- 店舗・顧客・予約・売上などの業務データを保持
- リレーションを整理し、整合性を保てる設計
- 定期バックアップと復旧手順を整備

## 管理画面

- 店舗スタッフ・管理者が利用する業務画面
- 権限に応じて、閲覧・操作できる範囲を分離
- 予約登録、顧客管理、売上集計などの日常業務を集約

## LINE連携

- LINEログインによる本人連携
- LINE Mini App によるアプリ不要の利用者体験（案件による）
- 通知・連絡導線としてのメッセージ送信
- Channel Secret やアクセストークンはシークレットとして管理し、コードや公開リポジトリには含めない

## VPS / Nginx

- Linux ベースのVPS上で運用
- Nginx をリバースプロキシとして配置し、HTTPS終端・ルーティングを担当
- フロントエンド・バックエンドへの振り分けを行う

## Docker

- フロントエンド・バックエンド・データベースなどをコンテナとして構成
- 環境差異を減らし、開発・本番で同じ構成を再現しやすくする
- 環境変数で接続情報を切り替え、シークレットはイメージに焼き込まない

## 外部サービス連携

- LINE（ログイン・Mini App・メッセージ）
- 必要に応じて、メール送信・決済・計測などのサービスと連携
- いずれもバックエンド経由で連携し、認証情報はサーバ側で安全に管理

## 今後の拡張

- 決済サービスとの連携
- 通知・配信機能の強化
- ダッシュボード・レポートの拡充
- スケールに応じたインフラ構成の見直し
