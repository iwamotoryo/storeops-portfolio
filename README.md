# StoreOps Portfolio

## 概要

StoreOps Portfolio は、実店舗ビジネス向けに開発・運用してきた業務システムの実績を、**公開できる形に匿名化・一般化してまとめた資料集**です。

美容室・ドッグサロン・レンタカーといった、予約と顧客管理を中心とする店舗運営の現場で、要件整理から設計・実装・運用改善までを担当してきました。本リポジトリでは、その経験をケーススタディと技術ドキュメントとして整理しています。

## このリポジトリの目的

- 転職・業務委託・カジュアル面談の場で、開発実績を安全に説明するため
- 「どのような課題を、どのような技術と設計で解決してきたか」を、第三者が読んでも分かる形で示すため
- 本番情報を一切公開しないという**セキュリティ意識を前提とした実績提示**を行うため

実際に動いている本番システムのソースコードや顧客データは、このリポジトリには含めていません。あくまで、考え方・設計・担当範囲を伝えるための資料です。

## このポートフォリオで伝えたいこと

私は、言われたものを作るだけの実装専任者ではありません。**現場の課題を整理し、業務フロー・画面・データベース・API・運用までを一貫して考えたうえでシステム化する**ことを得意としています。

- 実店舗ビジネス（美容室・ドッグサロン・レンタカー）の現場に入り、**予約・顧客管理・売上管理・LINE連携**といった、店舗運営の中核となる業務をシステム化してきました。
- 業態は異なりますが、いずれも「予約・顧客・売上が密接に絡み合う」という共通点があり、その関係をデータ構造として整理することに取り組んできました。
- 要件整理から設計、実装支援、テスト、運用改善までを通して関わり、**リリースして終わりではなく、現場で使われ続けるシステム**にすることを重視しています。
- AIを開発支援として活用していますが、要件整理・仕様確認・検証・運用判断は人間（私自身）が責任を持って行っています。
- 顧客の個人情報や売上を扱う仕事のため、**本番情報は一切公開せず、匿名化・一般化したケーススタディ**として整理しています。このポートフォリオ自体が、そのセキュリティ意識の表れです。

## 公開している内容

- 各システムのケーススタディ（背景・課題・解決方針・担当範囲）
- 一般化したシステム構成・DB設計・API設計の例
- セキュリティ方針
- AI活用方針
- 匿名化したスクリーンショット（順次追加予定）

## 公開していない内容

以下は**意図的に公開していません**。

- 本番システムのソースコード
- 本番DBのスキーマ実物・実データ
- 顧客情報（氏名・電話番号・住所・メールアドレス・免許証情報など）
- 売上の生データ
- APIキー、DB接続情報、LINE Channel Secret などのシークレット
- 管理画面URL、本番環境のドメイン・サーバ情報
- `.env` などの環境変数ファイル

詳細は [docs/security-policy.md](docs/security-policy.md) を参照してください。

## 代表実績

### 1. 美容室向け 予約・顧客・売上管理システム

予約受付、顧客カルテ、来店履歴、売上・スタッフ別実績の管理を一元化した店舗運営システム。
**Notionや紙などの分散管理から、自社の管理システムへの移行・運用改善**を行いました。
→ [ケーススタディ](case-studies/salon-admin.md)

### 2. ドッグサロン向け 予約・ペット管理・ホテル予約システム

飼い主とペットの情報管理、トリミング予約、コース・犬種・オプション料金、ペットホテル予約までを扱う店舗システム。
**飼い主・ペット・犬種・コース・ホテル予約といった、ペット業界特有の複雑なデータ構造を整理**しました。
→ [ケーススタディ](case-studies/dogsalon-admin.md)

### 3. レンタカー向け 予約・会員管理・LINE連携システム

店舗・車両・料金計算・予約・会員管理に加え、LINEログインや LINE Mini App によるマイページ提供までを扱うシステム。
**店舗・車両・料金計算・予約から、LINEを使った会員導線までを一体で設計**しました。
→ [ケーススタディ](case-studies/rentacar-system.md)

## 主に使用・関連した技術

これまでの案件で**主に使用、または関連してきた技術**を、代表的な技術要素として記載しています。すべての技術をすべての案件で使ったわけではなく、**案件により採用技術は異なります**。

| 分類 | 技術 |
| --- | --- |
| フロントエンド | Next.js / React / TypeScript |
| バックエンド | FastAPI / Python |
| データベース | PostgreSQL / MySQL |
| インフラ | Docker / Nginx / Linux（VPS） |
| 外部連携 | LINE（ログイン・Mini App・メッセージ）|
| CMS / ツール | WordPress / Notion |
| バージョン管理 | Git / GitHub |

※ 各ケーススタディには、その案件で実際に関わった技術要素を記載しています。

## セキュリティ方針

本リポジトリは「実績はあるが、本番情報は公開しない」という方針を徹底しています。本番コード・本番DB・顧客情報・売上の生データ・各種シークレット・管理画面URLは公開しません。スクリーンショットは匿名化したものだけを掲載します。

詳細は [docs/security-policy.md](docs/security-policy.md) を参照してください。

## AI活用方針

AIは開発の支援ツールとして活用していますが、要件整理・仕様確認・優先順位付け・テスト・運用判断は人間が行います。AIが生成したコードはそのまま採用せず、内容を確認したうえで反映します。セキュリティ情報や個人情報をAIに渡すことはしません。

詳細は [docs/ai-assisted-development-policy.md](docs/ai-assisted-development-policy.md) を参照してください。
